# 論理データモデル

旅行帳のデータの意味・関係・必須性を定義する。SQL型・制約・FK削除・認可の実装は [DB実装設計](./db-implementation.md)、ユーザー向け挙動は [MVP要件](./requirements.md)、判断理由は [設計判断](./decisions.md) を参照する。

- 旅行への所属は `trip_members`、作成者は `trips.created_by` で判断する。
- 旅程は旅行・日付ごとの `sort_order` が正式な順序。時刻で並べ替えない。
- 写真の公開フラグだけでは非参加者へ公開しない。旅行の閲覧資格も必要。
- 以下はデータ契約であり、すべての書き込み機能が実装済みという意味ではない。[実装状況](./db-implementation.md#11-実装状況と検証範囲)を確認する。

## 関係の全体像

| 関係 | 意味 |
| --- | --- |
| `auth.users` → `profiles` | ユーザーごとに最大1プロフィール。初回入力前は未作成を許容 |
| `auth.users` → `trips.created_by` | 旅行の作成者 |
| `trips`・`auth.users` → `trip_members` | 旅行とユーザーの多対多の参加関係 |
| `trips` → `itinerary_items` | 旅行に属する旅程。日付はアイテムが保持 |
| `itinerary_items` → `itinerary_photos` | 各アイテムに属する写真 |
| `auth.users` → `itinerary_photos.uploaded_by` | 写真の登録者。編集権限の所有者ではない |

ユーザー参照は `profiles.id` ではなく `auth.users.id` に向ける。認証情報はSupabase Authに任せる。`trip_days`、カテゴリ別詳細テーブル、メンバーroleはMVPに追加しない。

## profiles

旅行帳の表示名と任意画像を持つ。認証情報・旅行への参加状態は保持しない。

| カラム | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | PK。`auth.users.id` と同じユーザーID |
| `display_name` | ○ | 表示名。同名を許可し、識別子には使わない |
| `avatar_path` | — | プロフィール画像のStorageキー |
| `created_at` | ○ | 作成日時 |
| `updated_at` | ○ | 更新日時 |

認証後のS07初回保存で本人の行を作成し、通常編集でも同じ画面を使う。名前の自動生成・メールアドレス流用はしない。限定公開の閲覧にはプロフィールを要求しない。認証・招待復帰のフローと現在の表示名入力処理は [認証UIガイド](./auth-ui.md) を参照する。

本人が編集できる。他者の表示名・画像は旅行所属を確認するメンバー向け取得で扱い、非参加者には返さない。[取得契約](./trip-reads.md#参加者プロフィールの取得)ではプロフィール未作成の参加者を含めないため、返却件数を参加人数と同一視しない。

## trips

旅行本体。旅程・参加者の所属と公開範囲の基準になる。

| カラム | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | PK |
| `name` | ○ | 旅行名 |
| `start_date` / `end_date` | ○ | 旅行期間。同日旅行を許可し、終了日は開始日以降 |
| `thumbnail_path` | — | 旅行一覧等で使うサムネイルのStorageキー。旅程写真とは別管理 |
| `visibility` | ○ | 旅行の公開範囲。初期値 `private`、MVPは `private` / `unlisted` |
| `created_by` | ○ | 作成者の `auth.users.id` |
| `created_at` / `updated_at` | ○ | 作成・更新日時 |

`unlisted` は閲覧用共有リンクの資格が必要な限定公開。一般公開の `public` は将来対応で、MVPでは保存・閲覧を許可しない。非参加者の閲覧条件と返却範囲は [DB実装設計の公開取得](./db-implementation.md#shared-read) を参照する。

旅程日は原則として旅行期間内とする。期間短縮で範囲外旅程がある場合の確認・キャンセルは [MVP要件の日付](./requirements.md#日付)、期間変更と削除・画像清掃の整合性は [DB実装設計](./db-implementation.md#7-未実装の保存処理と整合性) に従う。

## trip_members

現在の旅行参加状態を表す。招待・閲覧用リンクの資格とは別に管理する。

| カラム | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | PK |
| `trip_id` | ○ | 参加している `trips.id` |
| `user_id` | ○ | 参加ユーザーの `auth.users.id` |
| `joined_at` | ○ | 参加日時 |

同じ旅行・ユーザーの重複参加を許可しない。作成者も旅行作成と同時に参加行を持つ。通常のメンバー間で閲覧・編集roleを分けず、旅行削除・招待・旅行と写真の公開設定変更だけは作成者限定とする。

作成者以外は自分だけ退出できる。作成者退出・他者強制退出・作成者移譲は提供しない。参加・退出の実装は [DB実装設計](./db-implementation.md#membership)、招待フローは [MVP要件の共有](./requirements.md#共有) を参照する。

## itinerary_items

場所・その場所で行うこと・移動を共通の旅程アイテムとして管理する。

| カラム | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | PK |
| `trip_id` | ○ | 所属する `trips.id` |
| `date` | ○ | 旅行内の日付 |
| `category` | ○ | `place`：場所・滞在中の行動、`transportation`：場所間の移動。独立した `action` は設けない |
| `title` | ○ | 名前。空文字不可 |
| `description` | — | アイテムごとに1つの共有テキストメモ。非参加者へ返さない |
| `sort_order` | ○ | 同じ旅行・日付内のユーザー指定順序。0以上の整数 |
| `time_type` | ○ | `none` / `exact` / `period`。初期値 `none` |
| `exact_time` | 条件付き | 正確な時刻 |
| `time_period` | 条件付き | 朝・昼・おやつ・夕方・夜の5択。保存値もこの日本語文字列 |
| `duration_minutes` | — | 分単位の正の整数。`place`は滞在、`transportation`は移動の予定所要時間 |
| `created_at` / `updated_at` | ○ | 作成・更新日時 |

| `time_type` | `exact_time` | `time_period` |
| --- | --- | --- |
| `none` | NULL | NULL |
| `exact` | 必須 | NULL |
| `period` | NULL | 必須 |

時刻・時間帯・推定時刻は順序の基準にしない。同一日での順序重複は現DBでは禁止しておらず、採番・一意制約は未決定。[旅程取得](./itinerary-reads.md)の同値時のID順は取得継続のためで、正式な順序仕様ではない。

内容入力で必須なのは名前のみ。日付・カテゴリ・順序は選択情報から設定する。未入力のメモ・時刻・時間帯・所要時間はNULLとし、時間未指定は `none`。メモ用の別テーブルや写真ごとのコメントは追加しない。

日単位更新・既存メモと写真の即保存・新規アイテムの一括登録は [MVP要件の旅程](./requirements.md#旅程)、競合・削除保護は [DB実装設計](./db-implementation.md#7-未実装の保存処理と整合性) を参照する。

## itinerary_photos

旅程のどの場所・移動に関連する写真かを管理する。画像本体はStorage、DBはキーとメタデータを持つ。

| カラム | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | PK |
| `itinerary_item_id` | ○ | 写真が属する `itinerary_items.id` |
| `storage_path` | ○ | 写真のStorageキー |
| `is_public` | ○ | 非参加者への閲覧許可の対象になれるか。初期値false |
| `uploaded_by` | ○ | 登録者の `auth.users.id`。登録時は対象旅行のメンバー |
| `created_at` | ○ | 登録日時 |

1アイテム最大5枚で、非公開写真も含む。アバターと旅行サムネイルは数えない。メンバーは全写真を閲覧・追加・差し替え・削除でき、任意の公開設定変更は作成者のみ。差し替えは作成者が行ってもfalseへ戻す。

`is_public = true` だけでは無条件公開しない。旅行の閲覧条件を満たす非参加者に限り公開写真を返す。非公開旅行では写真単独公開不可。将来の一般公開でもfalseの写真は非参加者に返さない。

`uploaded_by` は所有権ではなく登録履歴で、現DBでは差し替え時も元の登録者を保持する。差し替え者の履歴追加は未決定。画像のパス規約・配信・清掃は [Storage設計](./db-implementation.md#8-storage) を参照する。

## 削除と認可用データ

旅行削除で参加行・旅程・写真メタデータ、旅程削除で写真メタデータも削除する。Storage画像は別途清掃する。ユーザー削除で作成旅行や写真を自動消失させず、参照が残る場合は拒否する。具体的なFKは [DB実装設計](./db-implementation.md#4-fkと削除) に集約する。アカウント削除機能は未設計。

`private.trip_invitations` は参加資格、`private.trip_share_links` は閲覧資格を保持する実装済みの補助データ。通常の旅行取得へ混ぜない。列・認可は [DB実装設計](./db-implementation.md#2-スキーマと型) に記載する。編集権の補助データは未実装であり、`trip_days` の導入を意味しない。

## 未決定事項

DB・入力・画像・共有・編集に関する残件は [DB実装設計の未決定事項](./db-implementation.md#9-未決定事項)、UIの残件は [画面設計](./screens.md#8-残る未決定事項) に集約する。将来のモデル拡張として以下は未採用であり、先回りして列・テーブルを追加しない。

- 旅行ごとの表示名、旅行本体の説明、管理者概念。
- 写真の撮影日時・EXIF・表示順の保持、写真用サムネイル生成。
- ユーザー検索、他者強制退出、作成者移譲、アカウント削除方式。
